VL70-m MIDI Output

Kala can drive external MIDI hardware. The first (and so far only) target is the Yamaha VL70-m, a monophonic physical-modelling synthesizer. The integration turns Kala into the instrument's most capable controller it has ever had: instead of two or three expression streams from a wind controller, every expressive dimension the module offers — growl, throat formant, damping, absorption, embouchure, breath noise, and the rest — can be shaped as its own curve or driven by a Modifier container, all evolving independently on one sustained note.

The feature also closes the loop back to audio: a track can be baked — played once while Kala records the module's audio output — and the recording then plays as a normal track, so compositions are self-contained and the module is only needed at bake time.

What It Is

The VL70-m Out container sits in Kala's sound-engine graph like any other container, but instead of producing audio it emits MIDI: notes, pitch bend, and controller streams that play the external module. The same Modifier containers and connection combinators that drive internal synthesis drive the hardware.

  • Bake, then dispatch. Kala's engine is offline elsewhere (notes pre-render to buffers). Hardware cannot be pre-rendered, so the engine keeps the same philosophy: a background pass walks each note's curves and connections, applies the connection combinators, and produces a timestamped list of MIDI messages. A lightweight real-time stream plays that list in sync with the transport during playback.
  • Monophonic, by design. The VL70-m plays one note at a time. Two overlapping notes routed to it are an authoring conflict Kala flags (a warning in the log), not something silently resolved.
  • The patch owns the CC assignments. The module stores, per voice, which controller number drives which element parameter (the CONTROL NO. assignments, edited in VL-Wizard or on the module itself). Kala never rewrites those assignments — the container is a declaration of the contract: which parameters Kala drives, on which CCs, at what resolution. Design your patches (and their assignments) in VL-Wizard, then save a Kala sounit named after the patch it matches. The name match is a human contract Kala cannot verify.

Setup

MIDI Output Device

Open the Preferences tab (Ctrl+3) and find the MIDI Setup category:

  • Output device — the MIDI port the module is connected to (e.g. a USB interface's MIDI out). The selection is saved and remembered between sessions. Refresh re-scans for devices plugged in after the tab was opened.
  • Send test note — fires a short note through the selected port to verify the wiring.
  • Bandwidth test… — the measured-bandwidth harness; see Bandwidth Budget.

The score window toolbar has its own MIDI test button that sends the same hello note (breath CC2 + Note On A4, 500 ms) to the configured port.

Audio Return (for baking)

To bake a track to audio, the module's audio output must reach the computer's audio interface input (e.g. the UR22). Pick that input in the Bake dialog — see Baking to Audio.

The VL70-m Out Container

Add it from the Essential (Blue) menu of the sound engine: VL70-m Out.

Ports

  • Inputs: pitch, plus one port per active parameter row (each row's name — e.g. embouchure, damping). Toggling rows in the inspector adds or removes the matching port circle.
  • Output: midiOut — declarative; it carries no audio signal.

A note plays through the module when its variation's graph contains a VL70-m container. A graph with only MIDI-out containers and Modifiers is valid (the modifier subgraph still runs); mixed audio+MIDI graphs also work, at the same cost as an audio pre-render.

Pitch Bend Range sets the assumed bend sensitivity, but Kala does not rely on the static value: per note, a two-pass bake measures the note's real pitch excursion over its emission grid and sends an RPN 0,0 that covers it (up to the 24-semitone hardware limit), so wide glides stay continuous without re-triggering notes. The MIDI note number is fixed per note from its start pitch; everything else rides the bend wheel. Notes whose excursion exceeds 24 semitones log a warning and the bend clips.

Parameter Rows

Each row is the contract for one parameter: which CC it streams on (or which NRPN part address), at what resolution, where its resting value lives, and whether it returns to rest at note end. Per-row inspector controls:

  • Active checkbox — turns the row on (adds its input port and its curve name).
  • Name — the parameter (also its input port and its expressive curve name).
  • CC number — 1–95, for CC rows. This must match the patch's CONTROL NO. assignment on the module.
  • Resolution (ms) — how often the row's stream updates while it moves.
  • rest — the neutral value (0–127) sent at play start and, with reset @ end on, at note end.
  • reset @ end — return to rest when the note ends.
  • NRPN rows show their fixed part-offset address (e.g. NRPN 01 20) instead of a CC number.

No-curve semantics

The bake knows the whole piece, so end-resets are delta-skipped when the module is already resting:

  • An active row without a curve sends its rest value once at play start, and again at note end if reset @ end is on.
  • A row with a curve streams the curve, then sends its rest at note end (if reset @ end is on).
  • An inactive row sends nothing.
  • Stopping playback mid-note still sends the end resets.

The rest value

The patch's DEPTH and MODE decide where "off" lives: symmetric ±DEPTH CENTER BASE patches rest at 64; one-directional patches rest at 0 (or 127). Set each row's rest to match the patch — a row whose rest does not match the patch's center will linger at the curve's end value.

reset @ end defaults on for every row except volume. Leaving it on makes the note's release tail play at the neutral value — audible for multiplier-type rows, which is usually what you want; turn it off if a row should keep its last value through the release.

The CC rows are the twelve element parameters (physical model dimensions). The NRPN rows are part-level offsets — they need no CC assignment, cost little MIDI bandwidth, and can all stream at once. The default resolutions come from the measured bandwidth budget below.

The volume row

Volume (CC7) is special: it carries each note's dynamics curve, so it streams on the MIDI update interval grid and never resets at note end. It is toggleable (default on): with it off, no dynamics stream is sent at all, and loudness is expected to come from a breath (CC2) or expression (CC11) curve row instead, or from the module's own volume setting. CC7 dynamics is amplitude-only — the tone stays uniform at every level; a breath row recovers the breathier-tone-at-low-breath behaviour, and the two together decouple loudness from tone entirely.

Note: each part on the module has Rcv toggles (e.g. Rcv EXPRESSION) — a row only works if the part receives that controller. Likewise the per-voice EXPRESSION MODE (BC/VOLUME) decides what the voice's expression follows; even CCs' meanings are patch-level routing.

Curves

Every row except volume doubles as an expressive curve name: draw a curve named embouchure on a note and the row streams it. The score canvas's Show curves dropdown follows the container's active rows — toggling a row on adds its curve name, toggling it off removes it (non-destructively: the drawn curve stays on the note and reappears on re-activation). A row whose port has an incoming Modifier connection also leaves the selector, since the connection wins in the bake and a drawn curve there would be dead.

Modifier Connections

Any Modifier container (Envelope Engine, Physics, Drift, LFO…) can connect into a row's input port through the normal connection combinators, exactly as it would into an internal parameter:

  • Connection wins. A connected row streams the graph value; an unconnected active row keeps the named-curve path.
  • Mapping. Passthrough maps an Envelope's 0–1 output to CC 0–127 exactly like the curve path. Modulate pivots at 0.5, which sits on the row's rest value of 64.
  • Watch the source's range. Drift's output is a ~1.0 detuning multiplier, so a Drift→row connection saturates at CC 127 under passthrough or heavy modulate weight — use small modulate weights (~0.05–0.15), or an Envelope/LFO/Physics source, for full-range row motion.
  • The pitch port is not connectable. Pitch stays note-curve + vibrato driven; a connection to it logs one warning per bake.

Deactivating a row does not prune its canvas connections — a revived row silently keeps them (reloading the sounit drops them).

Pitch, Dynamics, and Timing

At play start, every note whose variation graph contains a VL70-m container is baked into a timestamped MIDI event list. During playback a Windows midiStreamOut stream plays that list, started at the same instant as the audio transport — internal audio and hardware stay in sample-accurate agreement over minutes of playback. The stream runs on a 1 ms tick, is split into ≤48 KB chunks (the API's per-buffer cap), and is torn down with a short grace period after the transport ends (All Notes Off, port closed).

  • Pitch — the nearest MIDI note is fixed per note from its start pitch; the cents remainder rides the pitch-bend wheel. Per-note bend sensitivity (RPN 0,0) is widened to cover the note's measured excursion. Vibrato is baked into the bend stream by the same code path the internal renderer uses.
  • Dynamics — the note's dynamics curve streams as volume (CC7) on the MIDI update interval grid.
  • Delta skip — unchanged values are never re-sent; note starts always send fresh values. This keeps the cheap tier (2–3 byte messages) well inside what twenty years of wind-controller streaming has proven the module can take.
  • Overlap — two notes sounding at once logs a conflict warning; the module is monophonic and the last note-on wins.

Bandwidth Budget

Controller bandwidth is two-tier: plain CC / pitch bend / aftertouch are cheap (2–3 byte messages); NRPN-addressed parameters cost 4–6 bytes per update. The scarce resource turns out to be neither: the module's physical-model recalculation is what saturates — element-parameter updates (the CC rows) are expensive regardless of encoding, while part-level NRPN offsets are cheap.

The bandwidth test

Settings → MIDI Setup → Bandwidth test… opens the harness used to measure all of this (it stops playback first — the engine would pollute the measurement). It sustains a note with a breath+bend baseline and offers three routes — CC-assigned element modulation, NRPN part offsets, and direct SysEx DEPTH streaming — each with a stress ladder (1 stream @ 50 ms up to 8 @ 6 ms, 1 ms opt-in), a manual mode (streams × interval) for boundary probes, audibility checks per parameter, verdict buttons, and bytes-per-second + overrun counters per step.

Practical budget

  • Stack 2–3 element curves at ≥ 25 ms per stream; the row defaults (25 ms) are the proven safe resolution.
  • NRPN part curves are free — up to 4 concurrently at 12 ms (again the defaults).
  • The MIDI update interval (volume + bend grid) can stay tight — the cheap tier handles it.

The bandwidth test assigns CCs via SysEx and leaves the module's voice edit buffer dirty — re-select the voice (or power-cycle) after a test session to restore the patch.

Baking to Audio

The module only exists in real time, so the bake pass plays the composition once while recording the audio-interface input carrying the module. The recording attaches to the track as a clip and joins the rest of the pre-rendered audio: it plays in sync during normal playback, and it is included in offline export. The composition becomes self-contained — it plays anywhere, hardware or no hardware.

Recording starts, then the normal playback path runs the transport while the capture (16-bit PCM through the same WinMM driver stack as the MIDI path) records the input. When playback stops, Kala:

  1. Aligns the recording's first sound to the earliest VL70-m note-on at/after the transport start (onset detection runs on a short-block RMS envelope with a noise-floor threshold, skips the stream-open click region, and requires the signal to persist).
  2. Trims the pre-roll and the click, and cuts the tail at the last signal plus a 500 ms pad.
  3. Reports the peak in dBFS with a hint (below −20 dB / above −1 dB) so the interface input gain can be dialed in without round-tripping through an external editor.

The clip caches its PCM at the right rate for each consumer — the device rate for live playback, the composition rate for export — so a bake stays in sync in both.

Freeze, Clips, and Overdub

  • Freeze. A track with a clip stops sending MIDI during playback — the clip replaces it. The module is now free.
  • Bake / VL toggle. In the mixer column of a baked track, a small checkable button switches between the recording (Bake, the default) and driving the module live again (VL) — an A/B comparison without clearing the clip. In live mode the clip is not mixed and the track's MIDI bakes again (the monophonic-overlap warning applies if other live MIDI plays at the same time).
  • Nudge. Two auto-repeat buttons (◀ ▶) under the toggle trim the clip's position in 10 ms steps (positive = later) — the fine trim for taste after auto-alignment.
  • Overdub stacking. Bake the next VL70-m track while the frozen ones play from their clips; the bake pass exempts its own target so the module still sounds for the take. Repeat per track.
  • The mono module, polyphonic. Play the stacked clips together — as many VL70-m parts as there are tracks, in sync, and all of them in the exported WAV.

Known Behaviors

  • Baked audio is a snapshot. Edit the notes or the patch after a bake and re-bake to hear it.
  • Files. Each take keeps its own <project>-bake-<N>.wav; the project stores absolute WAV paths, so moving the files breaks the clips.
  • 16-bit capture is the one compromise of the WinMM input backend (fine for a mix element).
  • Large glides can shift timbre. Many VL70-m voices route pitch bend into embouchure as well as pitch — check the voice's comment, counter-drive embouchure with its own row, or edit the voice in VL-Wizard.
  • Rows need the patch's cooperation. A CC row only works if the patch assigns that CONTROL NO. to the CC you chose, the part's Rcv toggle accepts it, and the rest value matches the patch's DEPTH + MODE centering.
  • Bandwidth-test residue. The test dialog writes CC assignments into the voice edit buffer — re-select the voice or power-cycle the module after a test session.
  • Deactivated rows keep their connections on the canvas (see Modifier Connections).
